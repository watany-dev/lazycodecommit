# update-docs

lazycodecommit（コマンド名 `lazycc`）の進化するソースコードと陳腐化しがちなドキュメントの差分を
体系的に埋めるスキル。5 フェーズで実施する。

## Phase 1: コード監査

実装の現状を把握する:
- 実装済みの画面・操作・キーバインド
- CLI 引数、設定ファイル、環境変数（AWS のプロファイルやリージョンの指定を含む）
- パッケージのメタデータ（バージョン、配布方法）

## Phase 2: 設計ドキュメント更新

`docs/dev/spec.ja.md` と `docs/adr/` を実装と突き合わせる:
- 振る舞いの変更を反映する
- ステータスラベル（設計中 / 未実装 / 実装済み）を実態に合わせる
- 必要な IAM 権限の表を、実装が呼ぶ CodeCommit / STS の API と揃える
- コマンド体系・共通フラグ・終了コード・キーバインドの表を実装と揃える

## Phase 3: README 更新

README に以下が含まれるか確認・更新する:
- プロジェクト概要 1 段落
- インストール／ビルド手順
- 使い方（起動方法、主なキーバインド、必要な IAM 権限）
- `make` ターゲット一覧

## Phase 4: 整合性チェック

全 Markdown 間で次を揃える:
- コマンド名・パス・キーバインド・設定キー・用語
- 言語規約（README を英語・日本語のどちらで持つかは docs の取り決めに従う）

## Phase 5: 報告

構造化レポートを出す:
- 更新したファイル一覧
- ドキュメント化候補（実装にあるが未記載の項目）
- 設計判断が必要な未解決の不整合
