# ADR 0005: 承認待ちの定義

## Status

Accepted.

## Context

ホームの「承認待ち」は、仕様書では「他人が作った OPEN の PR で、自分がまだ承認して
いない」という簡易条件にしている。CodeCommit にはレビュアーの指名がない。

この条件だと、承認ルールの承認プールに自分が入っていない PR まで出る。チームが
大きいリポジトリでは、自分が承認しても意味のない PR が並ぶ。

`GetPullRequest` の結果には `approvalRules` が含まれ、各ルールの
`approvalRuleContent` は承認プールのメンバーを ARN のパターンで持つ。

## Decision

承認待ちは、次をすべて満たす PR とする。

1. OPEN である。
2. 作成者が自分ではない。
3. 自分がまだ承認していない。
4. 承認ルールがない、または自分の ARN がいずれかのルールの承認プールに一致する。

「自分」の ARN は `sts:GetCallerIdentity` で取得する（仕様書）。

## Consequences

- 4 は `GetPullRequest` の結果だけで判定できるので、API 呼び出しは増えない。
- 承認プールのパターン照合を実装する必要がある。読めない形式のルールがあれば、
  その PR は承認待ちから外さずに残す（見落とすより、余分に出る方を選ぶ）。
